# What is excluded, how well, and what is still open (coverage-and-power ledger, 2026-10-17)

**Nothing in LP2 is solved.** Every negative in this repository is a statement of the form "a planted key of this kind, in this much text, would have been found by this test, and nothing was found".
This ledger lists, per hypothesis family, what was tested, the planted-control power that is on record, what the negative therefore excludes, and what it does NOT exclude. It is built from the logs
named in the last column; where a number is not in a log it is not here. Its purpose is to choose the next tests among the hypotheses that are genuinely open, not to repeat tests whose power is known.

*Status note: `docs/HYPOTHESES.md` and `work/log/phase9_hyp.md`, cited below, are the desktop's second session's work (H1-H12 with their controls); they were still uncommitted when this was written.*

*Update 2026-10-21 (tonight's work, phases 21-36): rows added or amended with a dated note; earlier lines are kept. Sources are the phase logs named in each row; the registry rows in `docs/registry.toml` carry the same numbers.*

Power legend: **strong** = planted keys of the realistic size are recovered at the exact setting; **partial** = recovered only in some windows or sizes (stated); **none** = the control fails or was
not run (the negative says nothing about the effect size LP2 shows).

## 0. Blind spots that apply to many rows

1. **Dictionary scores are blind if the separators are not the plaintext's word boundaries** (planted seed: score 33 with the English words' own separators, 0 with LP2's word lengths imposed,
   `phase9_boundaries.md`). Affected: `prng-all` (PHP, glibc, .NET, all sections), `prng-more` (window 0.7), `rescreen`, `dsearch`, prngx stage A, the dictionary version of hashscan. **Boundary-free reruns that exist:**
   all ten generators over all 2^32 seeds on window 0.7 (`prng-bg`); hashscan (19.2 M candidates) and the KDF lane (719,280 streams) on window 0.7; the OEIS lane (199,088 sequences, 36-rune windows); epoch-time seeds
   2011-2015 (8 generators) and small seeds below 2^27 (3 generators) on every section; millisecond timestamps for py3 and java (2013-09 .. 2014-01, window 0.7).
2. **IoC screens (kscreen) work on 300-rune windows.** Planted keys: recovered and above their null in 45 of 45 windows of 250-300 runes, but recovered in only 13 of 21 and above the null in 9 of 21 windows of
   0-149 runes (`results/kscreen/typo_plants.txt`). Any restart or heading test on a short window is weak.
3. **Scope of the windows:** the first 300 runes of each of the 8 sections (every offset of every keystream), plus 46 page starts, 10 headings, 22 typographic-mark windows. A key that is right only somewhere
   else is not tested.
4. **The anti-repeat rule is modelled as skip / coin (81%), as ciphertext feedback, as a step-domain rule, or as a null rune (H8).** Each has its own decoder; a mechanism outside these is not decoded.
5. **kscreen is blind to a two-layer cipher** (IoC about 1.1-1.2 after removing the outer layer, threshold 1.40); the laptop's `layer2` and the H1 design address that.
6. **Window length of the boundary-free statistic (audit by an outside LLM, 2026-10-17).** A correct key scores +7.3 per rune on Cicada's solved text (+7.1 to +7.9 on English), not the +10 once quoted: 120-rune windows pass the +300 gate in 99.6-100% of cases, 36-rune windows in about 29%. The OEIS lane used 36-rune windows (`phase10_deepseek_round3.md`).
7. **Seed coverage:** 32-bit seeds for the full sweeps, window 0.7 for the exhaustive ones; the 64-bit port covers py3 / ruby / java only.
8. **Plaintext language (project review, 2026-10-18, `results/analysis/assumption_checks.txt`).** The IoC rule is language-agnostic and robust (Cicada's solved text: every 300-rune window >= 1.57, 99.1% of 100-rune windows >= 1.40). The 120-rune boundary-free lanes (PRNG, hashscan, KDF) keep 98-100% power on Latin, German, French, Spanish and Italian; the SHORT-window lanes do not: with an English bigram table a true key passes +300 on 60-rune windows in 56% (Latin), 70% (German), 87% (French) and on 48-rune windows in 27%, 35%, 59%. The OEIS-lane power figures hold for English-like plaintext only.
9. **Decoders move the key pointer only forward at a collision.** Not decoded by any screen: runes that are inserted WITHOUT consuming a key value (unkeyed nulls, for example one per word), and extra key advances at layout events (word separators, line or page breaks). H8 as defined (the null spends the colliding attempt's key value) is aligned and visible; the unkeyed variant is not (`phase10_review.md`). **2026-10-18 update:** the `nulledge` engine option now decodes the deterministic variants - a keyless null at EVERY word-final or word-initial rune - and they are excluded for LP2 against the library (best 1.4163/1.4294 vs matched nulls 1.3901/1.3849, all hits fall to 1.04-1.06 whole-window; `work/log/phase12_review2.md`). The ~42%-of-words mixture (the word-length model's rate) is measured to have no powered IoC decoder: the free per-word beam inflates the random-key null to 1.75 (per-word null freedom = key-phase freedom) and the deterministic reading misaligns at the first null-free word (1.27). The layout pointer advance (`advsep`) is being built separately.
10. **A statistic that has power without the anti-repeat rule can be dead with it (2026-10-21).** DeepSeek's H2 coincidence statistic: z 41.7 on a planted tableau cipher without the skip rule, z 1.2 with the 81% rule (`results/analysis/proposals_h2_skip.txt`); the drift-aware version built in phase 32 recovers 0-6 of 24 plants at 300-1,524 runes (`phase32_h2_drift.md`). Any new statistic must be gated WITH the skip rule.
11. **Block-wise sign or direction rules are partly seen by the default engine (2026-10-21).** Layout rules from the page (0-1 sign changes in a 300-rune window, 2-3 for half-page rules) leave long correctly decoded stretches: the unsigned decode of a planted page rule reached up to 1.44 (`phase36_layout_rules.md`). A negative from the default campaigns therefore already covers part of the page-level rules, and a screen of them on the first 300 runes adds little.
