Scope: web hunts and datasets (part A). Discord part (B) was stopped by the owner's decision during the session (see "Searched and found nothing"). Nothing in LP2 is solved. Nothing downloaded; no code from third parties run; no Tor.

## Background (what the sources say)

- Liber Primus page 56 (as the community reads it) gives a 512-bit hash of a page on the deep web. An End's value is the SHA-512-length value held in `results/payload/hashes.txt`. The algorithm is not named in any source found; "512 bits" alone does not fix the function.
- The only public tool found for the hunt is the Firefox add-on "3301 Hash Alarm" (version 1.2, last updated 14 April 2021, GPL-3.0, per third-party mirror listings of the add-on). It hashes the requests a browser makes against the target and offers a menu of algorithms: SHA-512, SHA-3, BLAKE-512, BLAKE2b, JH, Skein, Grøstl, Keccak-3, Whirlpool, CubeHash, Streebog, MD6, LSH and others. Source: https://firefox.marketplace.browsertotal.com/pl/firefox/addon/3301-hash-alarm/ (mirror; the official store page was not reachable). The add-on's own code was not fetched and was not run.
- A Habr article (2014) describes a 2014 onion status page that grew to 512 characters. That is a character count, not the hash. Keep the two apart. Source: https://habr.com/en/articles/211428
- No community write-up found says what the hunters hashed, how, or which pages were excluded, beyond the items already in phase45 R2-17..R2-21 and phase52.

## 3. Top 3 untested leads, specified to run later

1. **L1, algorithm set on the held bodies (CPU job, not run here).** Inputs: the 1,913 unique bodies in the phase52 manifest (`work/ref/an_end_hunt/manifest.jsonl`, git-ignored) plus the 1,826 local files already hashed in phase52. Functions: JH-512, Skein-512 (all three variants), Grøstl-512, BLAKE-512, CubeHash-512 (standard parameters), MD6-512, LSH-512 (one size), Keccak-512 with the pre-FIPS padding. Variants: raw body; body without HTTP headers; LF-normalised; the phase52 text variants only where the body is text. Implementations from the published specifications, each checked on the published test vectors before use; no third-party code. Positive control: for each function, plant the digest of one held body; that body must be recovered (per function, 100%). Null: 0 full 512-bit matches over all digests; report the count of 16-hex prefix matches as a sanity check (expected chance about 10^-19 per pair). Cap bodies at 30,000 bytes for pure-Python functions as in phase52, and report the cap as a limit. Stop rule: any full match is verified by re-fetching the body and recomputing with an independent implementation.
2. **L2, Common Crawl CDX check (cheap, may find nothing).** Query the public CDX index for URL patterns `*.onion/*`, `*.onion.to/*`, `*.onion.cab/*`, `*.onion.city/*`, `*.onion.link/*`, `*.tor2web.org/*` and the 34 onion hosts listed in phase52 §1 (any crawl year 2013-2016). Record counts only. If any capture exists in 2013-2016, fetch that WARC record by byte range (under 1 MB each, total under 50 MB), and compute the same digest set as L1 on the payload. Positive control: one gateway page held in phase52 must be found in its WARC payload with the same digest. Null: the same run over 1,000 random captures from other hosts must give 0 full matches.
3. **L3, manual archive.today check of the 34 hosts (no bulk).** Per host, one lookup of archive.today for the host's gateway form (onion.to and tor2web where present). Record the number of snapshots and their dates only. If a snapshot exists for a 2014-2016 date, save its rendered text only by hand, not bulk. Positive control: one onion.to page held in Wayback (phase52) re-fetched from archive.today must match its Wayback body byte for byte, or the route is ruled out. Null: unrelated snapshots must give 0 matches.

## 5. Killed by known signal

- The 512-character growing page (2014, Habr) is a character count, not a hash; it does not give a 512-bit target. Killed as a hash lead.
- Any gateway-rewritten copy (onion.to, tor2web) cannot match an origin-page hash byte for byte; treat gateway matches as not counting unless the origin's bytes are shown. This limits L2 and L3 to low prior.
- DUTA-type text datasets cannot match a full-page hash (text extracts), so they are not leads for this hash.
