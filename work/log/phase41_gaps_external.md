| 1.1 | **Playfair-style digraphic fingerprint.** Playfair ciphertext never has equal letters *inside a pair* but can across pair boundaries; the pair alignment is therefore visible as a parity effect on doublets. Also: a digraph XY and its reverse YX appear with related frequencies, and a Playfair text has even length. | [Playfair notes (UCF)](https://www.cs.ucf.edu/~dmarino/ucf/cis3362/lectures/newlecs/Playfair.pdf), [Boxentriq Playfair](https://www.boxentriq.com/ciphers/playfair-cipher). Fetched as search snippets only; the property is textbook. Community echo: the [cicada_tools README](https://github.com/yo-yo-yo-jbo/cicada_tools) infers "Playfair-like" from LP2's doublet scarcity, with no numbers (README read, claim unsupported). | Split each word, line and section into aligned pairs from several anchors (word start, line start, section start, both parities). Compare doublet rate at pair-internal vs pair-crossing positions; count YX against XY (reciprocal digraphs); test whether the doublet deficit differs between even and odd absolute positions and between even and odd positions within a word. Null: shuffle words. | **No.** `obs-doublets` says "equally... inside words and across word gaps" but there is no parity-of-position split in the registry. | Trivial (seconds, pure counting) | This is the single cheapest check that a known cipher family with a *no equal letters* rule would fail or pass. A parity effect would also explain the odd word-length distribution (parity-padded words). Prior is low, because the deficit is only 81%, not 100%, and the lag-6 relation is not a Playfair property. |
| 1.2 | **Homophonic cipher with cycled homophones.** A homophonic cipher that rotates its homophones suppresses ciphertext doublets (plain EE becomes two different symbols). | Memory (standard homophonic-cipher folklore). | Test whether doublet-suppression is *plaintext-letter-dependent*: it is already known to be equal for all 29 runes (`obs-doublets`), which argues against it. ## 4. The page that hashes to An End, and the deep-web hint

* Per Boxentriq (fetched): the decoded An End text says a page hashes to a hex string beginning `36367763`; it is every pilgrim's duty to find it. A community tool, the [3301 hash alarm Firefox add-on](https://firefox.marketplace.browsertotal.com/sv-SE/firefox/addon/3301-hash-alarm/) (snippet; third-party listing), hashes every page and request a browser sees against many 512-bit candidates (BLAKE-512, JH, Skein, Grostl, Keccak, Whirlpool, SHA-512, BLAKE2b, CubeHash, Streebog, LSH...). That list is a **useful list of the hash functions to try**.
* The repo checked the 75 page scans against SHA-512 only (`page-scan-audit`: "no scan hashes to the An End SHA-512").
