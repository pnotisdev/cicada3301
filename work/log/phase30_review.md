## SEVERITY 3: failure modes that look like a negative
- A failed job does not stop the queue (documented), so a failed `gates` or `pdir-000` is followed by `verify-000`, which on an empty folder prints `0 vectors, candidates 0` and writes `verify_summary.txt` saying so: read it as a failure, not a negative (expected: 132 vectors per convention; `real/` must hold 132 tsv files). A failed `gates` (the quick self-test: reference, exhaustive, equivalence, 4 plants, null) does NOT block the 24 h run; check `pdir.tsv` for `gates ... ok` before trusting anything.
- `pdir_pilot.py` treats an existing tsv as finished. The engine writes its tsv only at the end of a vector (`File::create` after the merge), so a truncated file is possible only if the process dies during that write; `hits()` would then return 0.0 silently. Low probability.
- The poll `running()` returns 0 on any PowerShell error or empty output, which counts as idle; six such results in a row (2 minutes) would release the WAIT early. The CIM query is slow under load (mine took over two minutes) but did return output; an early release is possible, not observed.
