# R4 repair s05: power map of the unchanged mid arc for R4 plants (slots `any`), 2026-10-24

Nothing in LP2 is solved. Plants only; no LP2 ciphertext was scored. Idea 8 of `work/laptop_review/11_next_100.md`.

## Question
How does the recall of the unchanged mid arc (chanscreen v2 kind 3, word-start mask only, `S_guard >= T300 = 29.80`) depend on window length n and on a mis-set decoder nu or plant q, for R4 as fitted (null slot uniform in 0..L, "any")?

## Method (exact)
- Code: `work/r4fix/s05_power_map.py` (new). `make_r4` is s01's generator with an explicit seed and a window-length parameter (copied; `work/r4fix/s01_edge_plants.py` is imported only by the control). `search` is `plant_mid.search` with the decoder nu as a parameter (the original hard-codes 0.42) plus two extra columns (below). `plant_mid.guard`, `masks`, `P._init`, `lp_pilot_mid.lower()` imported read-only.
- Plants: one 450-rune window per plant, n = prefix of it (n 100 / 150 / 200 / 300 / 450). hold (`m04`) and spend x Cicada / English held plaintext x seeds 0-5 = **24 plants per cell** (seeds 6-11 added for base `any` at n 150 and 200: 48 plants there). Seeds `sha256("r4fix-s05|{mode}|{channel}|{src}|{i}")` (first 8 bytes); matched null plant = index `i + 1000` with an iid key (same layout), searched in the same stream. Sign +1 for even i, -1 for odd i. Plant null rate 0.45, plant q = frozen `q` of `{ch}|{src}|lib` (0.807-0.810, "0.81") unless overridden.
- Variants (one factor at a time; the decoder's own q table `C.Q_DECODER` is never changed): `base` (decoder nu 0.42), `nu030`, `nu055` (same plants as base), `q070`, `q095` (same seeds as base, so same words, plaintext, key stream and offset; only the repair draws differ: paired).
- Search: true (planted) stream only, both signs, every offset, 4 decoder channels (8 passes). Detected = band best (true sign and channel, offsets +-3 of the true one) >= 29.80. T300 is used at every n (it is frozen for n 300; at n 100 / 150 / 200 it is not calibrated).
- Run (3 workers, below-normal priority via SetPriorityClass in each worker; 98 MB per worker): `control`, then `run --variants base --modes any --ns 100,150,200,300,450 --nulls`, `run --variants base --modes interior --ns 100,150,200,300`, `run --variants nu030,nu055 --ns 100,150,200`, `run --variants q070,q095 --ns 100,150`, `run ... --nulls` for the nu variants at n 150, `run --variants base --ns 150,200 --seeds 6..11`, `redo` (see "alias fix"), `summary`. Records: `results/r4fix/s05_power_map/rec/`.
- **Alias fix (a mistake of mine, corrected):** the "wrong cell" of s01 / `plant_mid.search` excludes only the +-20 offsets around the true one. Library streams of about 2,000 runes (keyword streams such as `kw:ARRIUE`, period 6) repeat their key window, so an offset elsewhere carries the SAME key values and scores the same: that is an alias, not a wrong key. I first added a non-alias column that missed the +-20 band around each alias and the windows truncated at the stream end (two buggy versions, columns `wrong_nonalias`, `wrong_nonalias2`, discarded; the fixed column is `wrong_nonalias3`: drops +-20 around every offset whose key window, `n * channel factor + 16` values as in `hit_rule.py`, equals the true one, also truncated ones). All plants with n <= 300 (base) and the variants' n were rerun with it (old records in `rec_first_pass*`; the detection numbers and band scores are bit-identical in old and new runs, max difference 0). The n 450 records and the base `interior` records predate the fix for that column only.

## Controls
- **Positive (exact): PASSED.** The generator reproduces s01's plants bit for bit (cipher, masks, key, offset: identical for 8 of 8 plants) and the searches reproduce s01's records exactly: 4 `any` plants (m04 cicada 0, m04 english 0, spend cicada 1, 2) and 4 `interior` plants (m04 cicada 0, m04 english 1, spend english 0, spend cicada 0), each at n 150 and 300 with decoder nu 0.42, q frozen: band, winner score and detected / within3 flags equal s01's, **max |difference| 0.0** (`results/r4fix/s05_power_map/control_s01.json`). (The 8 are plants with 2,000-rune streams, chosen for cost.)
- **Null (matched iid-key plants, true stream searched at every offset / sign / channel, 12 per cell, seeds 0-2 x 4):** max winner score base `any`: n 100 -3.9, n 150 -19.8, n 200 -35.3, n 300 -70.0, n 450 -124.5 (s01: -18.7 at n 150, -73.2 at n 300). Mis-set decoder, n 150: nu 0.30 -23.3, nu 0.55 -17.6 (no inflation). No null reaches T300; at n 100 the null max (-3.9) is only 25.9 nats under the frozen T300.
- Reference `interior` (24 plants, own seeds, not s01's): 24/24 at n 100, 150, 200, 300, band medians 50.7 / 72.7 / 95.7 / 146.4 (s01's 12 plants: 73.6 at n 150, 155.2 at n 300), consistent.

## Result: recall against n (base: decoder nu 0.42, plant q 0.81, slot `any`)
| n | detected (Wilson 95%) | median band (min / max) | `interior` detected, median band | matched null max |
|---|---|---|---|---|
| 100 | 16/24 (47-82%) | 39.9 (13.9 / 54.5) | 24/24 (86-100%), 50.7 | -3.9 |
| 150 | 45/48 (83-98%) | 59.6 (16.1 / 95.3) | 24/24, 72.7 | -19.8 |
| 200 | **48/48 (93-100%)** | 76.8 (38.0 / 117.9) | 24/24, 95.7 | -35.3 |
| 300 | 24/24 (86-100%) | 117.1 (79.9 / 149.9) | 24/24, 146.4 | -70.0 |
| 450 | 24/24 (86-100%) | 172.8 (113.5 / 235.2) | not run | -124.5 |
- **Smallest n with `any` recall >= 90% (Wilson lower bound): n 200** (48/48, lower bound 93%). n 150 has point estimate 94% (45/48) but a lower bound of 83%; n 300 and 450 have only 24 plants each, so 24/24 gives a lower bound of 86% (it cannot reach 90%; n >= 200 is saturated in every plant, minimum band 38.0 at n 200 against 29.8). So "recall >= 90%" is shown for n >= 200, and plausibly holds at n 150 (point 94%) but is not shown there.
- The cost of edge nulls is clear at n 100: `any` 16/24 against `interior` 24/24 (one-sided Fisher p 0.002, independent plants, different seeds). Median band (true cell) any vs interior: 39.9 vs 50.7 (n 100), 59.6 vs 72.7 (150), 76.8 vs 95.7 (200), 117.1 vs 146.4 (300): -11 / -13 / -19 / -29 nats, i.e. about 0.11 nats per rune of window (the median band rises about 0.38 nats per rune in `any`, 0.48 in `interior`).
- Undetected plants are the ones with many edge nulls: n 100 detected / undetected median edge nulls 4 / 5, median band 41.7 / 21.8; n 150 (3 misses) 11 edge nulls median (6 for detected); band against edge-null count correlation -0.43 (n 100) and -0.66 (n 150), slope -2.9 and -4.3 nats per edge null (s01: -1.8 to -1.9 per edge null at n 150 / 300 with the plants it had). 44% of all nulls are edge nulls (n 300 records), as in s01 / the brief.
- **Undetected plants, true cell vs best wrong cell** (full list with the numbers in `summary.txt`): all 8 misses at n 100 and all 3 at n 150 have the true cell at 13.9-28.9 (n 100) / 16.1-28.3 (n 150), i.e. 1-16 nats under T300; the best cell outside the true key window is far lower (n 100: -4.8 or lower; n 150: -28.6 or lower; non-alias column), so no miss is a "wrong key won". Several misses have a higher-scoring cell that is not a different key: another decoder channel at the true offset or a periodic-stream alias (e.g. n 150, spend english 6: true 28.3, winner 42.6 = alias; non-alias best -56.3). Detections that were "not within 3 nats" in the raw column (21/24 at n 100, 44/48 at n 150, 44/48 at n 200, 20/24 at n 300) are **all** within 3 nats once aliases of the true key window are removed (24/24, 48/48, 48/48, 24/24; the n 300 / 450 within3 numbers in `summary.txt` for n 450 are raw only). s01's "wrong cell above the true one" case (spend english 0, n 150/300, `zeta(3)` stream) is the hold channel at the true offset (winner `(+1, hold, 8376)` inside the +-20 band; best wrong cell -17.1 / 37.5), not a wrong offset.
- **Recall is also lower for the long-stream plants?** Not shown: n 100 long (20,000-rune) streams 4/8, short 12/16; n 150 13/14 and 32/34 (small numbers).

## Result: mis-set parameters (24 plants, seeds 0-5, `any`; paired against base on the same plants)
| variant | n 100 detected | n 150 detected | n 200 detected | median change of the true-cell score vs base (worst / best plant) |
|---|---|---|---|---|
| base nu 0.42, q 0.81 | 16/24 | 23/24 | 24/24 | 0 |
| decoder nu 0.30 | 16/24 | 23/24 | 24/24 | -1.26 / -1.17 / -1.43 nats at n 100 / 150 / 200 (worst plant -3.1 / -4.9 / -5.9) |
| decoder nu 0.55 | 17/24 | 23/24 | 24/24 | +0.12 / -0.14 / -0.40 (worst -2.3 / -2.4 / -3.1) |
| plant q 0.70 | 19/24 | 23/24 | not run | 0.00 / 0.00 (plants differ after the first repair; range -2.8 to +17.4, -4.1 to +20.0) |
| plant q 0.95 | 17/24 | 23/24 | not run | 0.00 / 0.00 (range -9.6 to +12.3, -17.1 to +13.3); median band 34.6 (n 100), 54.4 (n 150) against 39.9, 58.5 |
- **Mis-setting nu by about 30% either way (0.30 / 0.55 for plants at 0.45) costs no detection and a median of about 1.2-1.4 nats (nu 0.30) or 0.1-0.4 nats (nu 0.55); the worst plant loses 5.9 nats.** One plant is gained at n 100 with nu 0.55; no plant is lost anywhere (lost 0, gained 0-3 in every cell). Null maxima at n 150 do not move (-23.3 / -17.6 against -19.8).
- **A mis-set repair rate q (decoder keeps its q) costs no detection in the cells run.** At q 0.95 the plants lose up to 17 nats in the worst plant (n 150) and 4 nats in the median band; at q 0.70 the median is unchanged and the best plant gains 17-20 nats (fewer repairs, so fewer key-advance anomalies the decoder must absorb). The detection counts (19, 17 of 24 at n 100) differ from base (16) only by plants near T300, a gain of 1-3 plants, not a loss. Not run: q at n 200 / 300 (saturated in base) and nu / q jointly.

## What this does NOT exclude
- Anything about LP2's actual key family: plants use library streams (the true stream, the decoder's best case); the real search is against 1,439 streams x offsets. At n 100 / 150 / 200 the whole-library null tail is not measured (the single-stream matched null is -3.9 / -19.8 / -35.3, but 12 plants per n). T300 = 29.8 is a threshold frozen for n 300; at n 100 a calibrated threshold would be lower, so the "16/24" is the recall at an uncalibrated threshold: the weakest n 100 plant is at 13.9 and the matched null max -3.9, which would separate them only if the library-wide null tail at n 100 stays under about 14 (not measured).
- One value of the plant null rate (0.45), one null per word, uniform null value, repair writing T(c-6), Cicada and English plaintext only, hold and spend planted channels only (skip5, coin not planted), word edges flagged as in s01 (word-start flag on a slot-0 null). Plant nu and q varied one at a time (no joint mis-setting; q 0.70 / 0.95 only at n 100 and 150; nu 0.30 / 0.55 at n 100-200).
- 24 plants per cell: a lower bound of 86% at 24/24. Only n 150 and 200 have 48; the n 150 recall (45/48, 83-98%) is statistically compatible with 90%.
- Seeds 6-11 were added after seeing seeds 0-5 at n 150 / 200 to reach 48 plants (done to tighten the bound, decided before seeing seeds 6-11 results; the 3 n-150 misses are 1 in seeds 0-5 and 2 in seeds 6-11).
- n 450 was not run for `interior` or for any variant; no window shorter than 100.
