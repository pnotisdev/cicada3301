Nothing in LP2 is solved. Reviewed: `work/log/phase23_book_key_decoder.md`, `work/book_key_decoder.py`, `work/book_key_screen.py`, `results/analysis/book_key_screen_desktop.txt` (liber_al, blake_songs, blake_mhh done at review time).

## Verdict
No finding invalidates the overnight negative. The decoder models what it claims, the threshold transfers to LP2, and the step of 8 is safe. The known sentinel defect is real but cannot hide a hit at a valid offset. What the negative covers is limited by the gate's own power (about 10-20% of true windows lost) and by the scope list in the spec; those limits are inherited, not new.

## 1. Does the beam model c = p + pi(k) with unknown pi AND the skip rule? (checked: yes, with two approximations)
- `beam_decode` scores sum over key letters g of logsumexp_v (G[g,v]) - log 29: the shift pi(g) is integrated out per group, no permutation assumed, so any table is covered. The pointer moves +0/+1/+2 per rune with ln(0.81/29) = -3.58 nats per skip. A true book key at the true offset is scored.
- Approximation A: a skip is allowed at any rune (not only where a collision would have occurred) and the 0.19 factor for non-skipped collisions is omitted. Null and signal are both slightly higher; the threshold was calibrated by the same code on uniform-key ciphers with the skip rule (the tail), so it is consistent. The exact collision-conditioned likelihood is used only in the EM stage, not for detection.
- Approximation B: 8 free start pointers (spread 8) with no penalty. It is also in the tail calibration (`decode(..., spread=8)`), so it is in the null.
- Gate numbers (own re-check, 12 plants each, flattening table, q = 0.81, 729 runes, Liber AL as the key): digraph key 10/12 above the frozen -0.0112, letters key 12/12 above -0.0417. Plant scores sit at about +0.24 to +0.32 per rune while the null is -0.23 +- 0.02: the signal is **bimodal** (found at about +0.24, or lost to the null level), so the threshold position between -0.23 and +0.24 does not matter; the power is the path-loss rate of 10-20% per window (gate table: 80-93% per 729-rune window; the screen's selftest: 9/12 plants). With 8 windows a continuous key is missed with probability about 1e-6 if the misses were independent; a key that restarts at an unknown book offset in each section is found in a given section with 80-93%. This is the actual size of the negative.
- Threshold transfer to LP2 (checked in the summary): LP2 window means/sd match the gate tail (digraph -0.2301..-0.2390 +- 0.0200-0.0217 against -0.2312 +- 0.0213; letters -0.2370..-0.2519 +- 0.0207-0.0227 against -0.2441 +- 0.0220), and the best of about 2,600 offsets per window gives gate z +2.9 to +4.4, what a null of that size predicts. LP2 behaves like the null and shows no unexpected tail. A genuine hit needs z about +10; a plant gives z +20.
- Letter-spelled plaintext (the word-length evidence prefers it; the decoder's model f is digraph Walden): 12 plants with Emerson plaintext spelled letter by letter: digraph key 10/12 above threshold, letters key 11/12, against 10/12 and 12/12 for digraph plaintext. No visible power loss at this sample size (12 plants: a loss of 15 points would not be detected).

## 2. Offset step 8: safe, no alias band needed (checked)
Each true offset o lies in exactly one grid cell [g, g+7], g = o - o mod 8, and `beam_decode` starts 8 states at g..g+7 (`spread`), so the true start is always among the starts. Check on a plant at offset 8003 (grid point 8000), score per rune at grid points 7960..8048: -0.22, -0.25, -0.21, -0.20, -0.21, **+0.224**, -0.22, -0.22, -0.27, -0.26, -0.23, -0.23: only the true cell scores; the cells at +-8 are at the null. With spread = 1: offsets -4 and +4 from the true one are at the null (-0.216, -0.269), while -1 and +1 still score +0.20 / +0.22 (one pointer step is repaired by a skip move), so there is a +-1 alias but none at +-4. A true offset between grid points is therefore NOT missed; the cost is that 7 of 8 starts are redundant per cell, which the tail already contains.

## 3. The sentinel defect (confirmed; harmless for hits)
- Cause: `beam_decode` returns `-1e18` when no state survives (every pointer reached the end of the key). Score per rune = -1e18/729 = -1.37e15. It happens at the last grid offset(s) of a book, where fewer than about 790 key runes remain (checked on Liber AL: digraph last offset 21256 with 777 runes left, windows 0.8 and 0.12; letters offset 22752 with 776 left, windows 0.12 and 0.13, and offset 22744 with 784 left for window 0.15). My inference (not proven): noise paths use extra skips (up to about 50 more than the true key's), so all 64 states run past the key end when the margin is only about 48 runes.
- Effect: the sentinel enters the chunk's `stats` sum and sum of squares, so the per-window mean, sd and "own z" in the summary are garbage (mean about -5e11, sd about 2.7e13, own z printed as +0.0) for every window that had one: 22 of 32 window rows in the first three books. "gate z", "best" and the HIT list are unaffected: `top` and `hits` are selected from the individual scores, and a sentinel is the smallest value, never in the top and never above the threshold.
- Can it hide a hit? Only at the final few grid offsets, where fewer than about 830 key runes remain and a true key would also run out within the window. The hidden region is at most a few grid points per book (3 of 2,658 for Liber AL, 0.1%; for the 3.0 M-rune KJV 0.0001%). **No hit at a valid offset can be hidden.**
- Fix (not applied; the queue reads these files): in `scan()` drop scores below -1 from `n`, `sum` and `sumsq` and record the dropped count (or write them as NaN and skip them in `summary`). The old sums cannot be repaired from the chunk files (the printed sums absorbed 1.37e15 and lost their real digits); the repair is to delete the final chunk of each book and spelling (the one holding the grid end) after the queue finishes and rerun it with the patched `scan()`. Until then read the "gate z" column only.

## 4. Other findings, lower severity
1. **Scope inherited from the spec (not bugs, but they bound the negative):** the model needs English-like plaintext, the skip rule at q = 0.81 (the coin variant and other q are not simulated), editions identical to our copies (a letter extra in our copy needs a backward step the decoder lacks), keys that are the book read forward with step +1 (not backward, not sums or hashes of the book). Agrippa and the Welsh texts are raw OCR, so a negative there is weak.
2. **Gate calibration is thin:** the 729-rune tail uses 2,000 decodes of 40 distinct uniform-key ciphers (one cipher per 50 offsets); the p = 5e-10 threshold is an exponential extrapolation from the top 5% (100 points). The false-positive rate at -0.0112 is not verified at 1e-9, but the bimodal signal makes the exact cut irrelevant, and LP2's own scores support the null description out to z about +4.4.
3. **Windows:** the first 729 runes of each of 8 sections only; section 0.10 (9 runes) is skipped. A key that restarts mid-section is seen only if the first 729 runes carry it; a continuous key shows in all 8 windows. A key restarting at book offset 0 in every section is covered (offset 0 is a grid point).
4. **Selftest pass mark is loose:** 4 of 6 plants per spelling passes it; the run gave 9/12. My re-check gives 43/48 (90%) across the four plaintext/key spelling pairs, consistent with the gate's 80-93%.
5. **Key text preparation:** `to_runes` replaces non-letters with spaces (digits and punctuation vanish and move no pointer); QU becomes CW, V/K/Z/Q follow the repository aliases; accents are stripped. Numerals read as words, or Roman-numeral transliteration, are not tried. Liber AL's text includes the Comment, as the spec says.
6. **Stage 2 does not exist yet** (handover item); any HIT found overnight waits for the verifier, which has to be gated on plants first.

## Ranked list
1. (Medium, scope not bug) Bimodal path loss: 10-20% of true 729-rune windows are lost; a per-section-restart key is found with 80-93% per section. The negative is exactly this strong.
2. (Low) Sentinel at the last grid offset: corrupts per-window mean, sd and "own z" (22 of 32 rows so far), cannot hide a valid-offset hit. Fix in `scan()` and rerun the last chunk per book after the queue ends; read "gate z" meanwhile.
3. (Low) Threshold tail is extrapolated from thin data; irrelevant for bimodal signals; LP2's own scores match the null to z +4.4.
4. (Info) Offset step 8 is safe (the 8 free starts cover every offset); +-1 alias only, none at +-4.
5. (Info) Letter-spelled plaintext does not visibly lower power (n = 12).
6. (Info) Inherited scope limits: q, coin variant, editions, OCR texts, non-forward keys.
