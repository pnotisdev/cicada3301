## What this tests

The H5 first-slice model `c_i = D(p_i) + t_j + w_(j mod L) + b (mod 29)` (docs/HYPOTHESES.md
H1) with `t` = ANY stream of the flat-IoC library (`work/kscreen/data/library_flat.ksb`,
581 streams) and `w` = an unknown keyword of period L 2..20, both anti-repeat models
(0 = skip, 1 = coin), the numba-first-look convention (the totient-alone pass over the same
windows was negative: `work/h5slice/lp2_look.txt`, zero cells >= 1.6). This campaign is the
remaining test: WHICH of the library's streams, if any, hides a keyword.

## Grid

* 8 section windows, first 300 runes of each of `work/kscreen/data/segments.txt`
  (seg0.7, seg0.8, seg0.9, seg0.11, seg0.12, seg0.13, seg0.14, seg0.15; prev rune from the
  W line) — `data/lp2_windows.txt`, generated by `gen_windows.py`.
* Offsets 0..1999 x L 2..20 x models {0,1} x 581 streams =
  **353,248,000 decodes** (608,000 per stream), abort (120, 0.9), engine `fast`, 8 threads.
* Chunks are offset blocks of 10 offsets, submitted in offset-block-major order (a wall cap
  gives every (window, stream, model) the same offset prefix — the lp2_look convention); the
  TSV is flushed after every chunk, progress goes to stderr every chunk.
* Streams shorter than offset + 300 + 107 are skipped at those offsets (16 of the 581
  streams are shorter than 2407 values; min length 2028).

## The extension (what changed in h5rs)

* `src/main.rs`: a KSB1 reader (`load_ksb`, format constants copied from
  `work/kscreen/src/main.rs`: magic "KSB1", u32 LE count, per stream u16 LE name length +
  UTF-8 name + u32 LE length + values mod 29) and `cmd_sweep_file`:

```
h5rs sweep <windows.txt> file:<lib.ksb>[:<name>|all] <off0> <off1> <L0> <L1> <model> <threads> <out.tsv>
           [--hits <t>] [--engine e] [--chunk <offsets>] [--progress <N>] [--best]
```

  * `model` = 0, 1, or **2 = both models** (file: mode only).
  * One TSV, columns `stream offset L model window IoC`, only cells with IoC >= `--hits`
    (**default 1.5** in file: mode); rows appear in offset-block-major order, sorted within
    each block. `--best` appends a `best <stream> <off> <L> <model> <window> <IoC>` section
    with the best cell per (stream, window, model) regardless of the threshold
    (off = -1 means the stream had no cells).
  * The item selector splits at the last `:` (so Windows drive letters work); an item name
    must not contain `:`.
* The existing `tot` / `rand:<seed>` sweep is unchanged and bit-identical (re-verified:
  the 312-check parity gate passes on the modified binary — parity.txt, 16,258 dec/s on 8
  threads under the current desktop load — and control (b2) shows the Python-replicated
  null stream and the internal `rand:` generator give identical per-cell IoCs across a
  whole grid).

## Launch (NOT DONE YET - parent wrap-up order stopped here)

```
Start-Process -FilePath cmd.exe -ArgumentList '/c','work\h5rs\launch_campaign.bat' -WindowStyle Hidden
```

`launch_campaign.bat` (run from the repo root) does, in one detached job:

1. the real sweep: 581 streams -> `results/h5rs_flat_sweep.tsv` + `results/h5rs_flat_sweep.log`
2. then the matched-null sweep: `data/null8.ksb` (8 replicates, seeds 9000..9007) over the
   same grid -> `results/h5rs_flat_null.tsv` + `results/h5rs_flat_null.log` (with `--best`)

### Kill / resume (NOT resumable)

* The job is **not resumable**: a kill discards nothing except the partial TSV is left
  behind, and a restart begins **from zero** (the launcher recreates both outputs).
* Kill: `taskkill /F /T /PID <pid>` where `<pid>` is the launched cmd's PID, or
  `taskkill /F /IM h5rs.exe` (kills the engine; the bat then runs step 2 and exits).
* Check: `Get-Content results\h5rs_flat_sweep.log -Tail 3` (chunk counter, cells, rate,
  eta) and `(Get-Item results\h5rs_flat_sweep.tsv).Length` / row count.
* Restart: rerun the launcher. Before a restart after a kill, the partial TSV/log are
  overwritten automatically — move them aside first if you want the partial grid.

## Reading the TSV

* `#` lines are headers. Data rows: `stream<TAB>offset<TAB>L<TAB>model<TAB>window<TAB>IoC`
  (IoC with 6 decimals; the >= 1.5 filter uses the full-precision value).
* Rows are in offset-block-major order: 200 blocks of 10 offsets; inside a block sorted by
  (stream, offset, L, model, window).
* The null TSV additionally ends with a `best ...` section: the best cell per
  (stream, window, model) even below 1.5. The **window's matched-null max** for the
  candidate rule = the max of the 8 null `best` IoCs for that (window, model).

## Candidate rule (applied AFTER the sweep, not by the engine)

A real-sweep cell is a CANDIDATE (flagged UNVERIFIED) iff:

1. its periodic IoC >= **1.6** AND >= **the window's matched-null max + 0.15**
   (matched null: the 8 replicate streams of the same grid, same window and model;
   expected null max ~1.3 over 608,000 cells/window), then
2. it is re-decoded WHOLE-WINDOW in Python (`work/h5slice`, beam 64, max_em 10, verified
   init — the h5slice.redecode conventions of `work/h5slice/lp2_look.py`), and
3. only if the whole-window re-decode holds, the whole-section English verification of
   `docs/CAMPAIGNS.md` runs ("If something passes": rerun by hand, check a second section,
   write up in `work/log/`).

A cell passing 1-3 is still not a decryption until the whole-section verification passes.
Every candidate so far, from any method, has been selection noise
(`docs/CAMPAIGNS.md`).
